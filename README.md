# JEV 모델 평가실

외부 멀티 LLM 서비스에서 복사한 한국어 답변을 독립적으로 평가하는 로컬 MVP입니다. 데이터와 API 키는 브라우저 저장소에 두지 않습니다. 입력과 평가 결과는 로컬 SQLite 파일에 저장되고, TypeSafe API 호출은 로컬 서버가 수행합니다.

## 실행

Python 3.12 이상만 필요합니다.

```bash
cd jev-evaluate
cp .env.example .env
# .env를 열어 TYPESAFE_API_KEY에 실제 키를 입력
python3 server.py
```

브라우저에서 `http://127.0.0.1:8787`을 엽니다. 서버는 실행 위치와 관계없이 이 폴더의 `.env`를 읽습니다. 이미 셸 환경변수로 지정한 값이 있으면 환경변수를 우선합니다. API 키 없이도 케이스 저장과 CSV 내보내기는 사용할 수 있지만 JEV 평가는 실행되지 않습니다.
결과 화면에서는 답변별 평가 또는 아직 평가하지 않은 답변의 일괄 평가를 실행할 수 있습니다. 일괄 평가는 API 제한을 피하기 위해 순차적으로 호출되며, 첫 오류에서 중단됩니다.

고정된 JEV 버전을 사용하려면 다음처럼 실행합니다. 임계값으로 모델을 비교하는 정식 실험에서는 `jev-latest`보다 고정 버전을 권장합니다.

```bash
python3 server.py --model jev-1.13.0
```

데이터베이스 기본 위치는 `data/evaluations.db`입니다. 다른 위치를 쓰려면 `--db` 옵션을 사용합니다.

## 평가 기준

품질 점수는 지시 준수, 관련성, 완전성, 표면 정확성, 명확성·스타일, 종합 품질의 긍정 확률을 0-100으로 변환한 값입니다. 근거 없는 단정, 조작, 치명적 실패는 별도의 위험 확률입니다.

정답이나 외부 근거가 없으므로 `표면 정확성`은 객관적인 사실 정확도가 아닙니다. 제공된 질문, 대화 기록, 첨부 텍스트 안에서 명백한 오류와 모순이 없는지를 뜻합니다. 코딩 답변 역시 실행 테스트를 하지 않습니다.

## 줄별 근거 연결

첨부 문서 텍스트가 있으면 비어 있지 않은 각 줄에 `E1`, `E2` 같은 ID를, 모델 답변의 각 줄에는 `A1`, `A2` 같은 ID를 자동으로 붙입니다. 애플리케이션이 문자와 단어 중복을 이용해 답변 줄마다 관련 근거 후보를 최대 6개 먼저 고릅니다. JEV는 후보만 보고 하나의 Choice 질문으로 다음을 함께 판정합니다.

- 선택한 근거가 답변을 직접 뒷받침하는지 또는 충돌하는지
- 가장 직접적인 대표 근거 줄 ID
- 직접 관계가 없으면 `NONE`

JEV는 `SUPPORTED__E3`, `CONTRADICTED__E3`, `NONE` 같은 정형 선택지만 반환하고 화면의 문장은 저장된 원문을 그대로 사용합니다. 화면에는 실제 근거 줄이 선택된 항목만 표시하며 `NONE`인 항목은 숨깁니다. 근거와 충돌하는 원문이 선택된 경우에는 반대 근거로 표시합니다. 문단 전체를 한 줄로 붙이면 하나의 판정 단위가 되므로, 의미 단위별로 줄바꿈해서 입력하는 것이 좋습니다. 한 번의 평가에서 답변은 최대 30줄, 첨부 근거는 최대 120줄을 검색합니다. 근거 연결이 포함된 평가는 품질 평가와 근거 평가를 각각 한 번씩, 총 두 번의 JEV API 호출로 수행합니다. 품질 요청에는 원문을, 근거 요청에는 줄 번호가 붙은 답변과 후보 근거만 보내 중복을 피합니다.

## 권장 소형 실험

- 질문 24개
- 질문마다 6개 모델의 답변, 총 144개
- 코딩 6개, 강의·첨부자료 6개, 일반지식·설명 4개, 추론·문제해결 4개, 지시사항 준수 4개
- 최소 24개 답변을 사람이 같은 기준으로 재평가
- 질문별 프롬프트와 설정을 모든 모델에 동일하게 유지
